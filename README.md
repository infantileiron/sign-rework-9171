# 桥语手语 · 视频返工工时比选

桥语手语制作工作台为新片预估返工工时，用独立摄制组的真实结算检验估算在组间迁移时的误差。

## 工作场景

桥语手语是一家模拟的无障碍视频制作团队，分 6 支摄制组，为政务窗口、社区门诊、图书馆和轮渡站制作手语导览。上游制片助理从分镜单提取成片分钟、镜头数和背景切换次数，后期剪辑在返工结算表补录总工时。过去制片人从共享表格挑几个相似项目来排班，容易遇到三个问题。

- 摄制组内的镜头模板与返工习惯相似，混在一起随机切分会高估模型跨组效果。
- 实际工时、复审次数等结算数据在接单时还未知，用它们做预测会把结算信息带回排期。
- 排期表中的公式和样本会被覆盖，制片人很难复核某批预测是用哪版特征计算的。

工作台把结算工单、特征版本和留组报告串起来。业务负责人复核后发布，排期人员可下载逐单误差明细，并在报告上估算下一条视频所需工时。

## 一天的操作剧本

1. 09:00，分析员周岚打开「工单样本」。种子数据有 48 条工单、6 支摄制组，每组 8 条。`QY-0101` 是晨桥组的《政务服务｜办事导引》，结算返工 2.52 h。
2. 09:10，在「摄制组名册」筛选渡口组。根据 `QY-0609-轮渡服务结算.xlsx` 的模拟结算录入《轮渡服务｜无障碍乘船指引》，成片 5.5 分钟、22 个镜头、换景 2 次、返工 7.60 h。渡口组增至 9 条。
3. 09:15，在「候选特征」保存 `轮渡排期 · v3`，勾选三项接单特征，设定 α = 0.18。已有 `接单三项 · v1`（α = 0.10）和 `时长与镜头 · v2`（α = 0.20）可供重跑。
4. 09:20，在「按组交叉验证」选择新版本并将渡口组整组留出。确认 5 个开发组、40 条开发工单和 9 条独立留出工单，再提交计算。
5. 09:21，后台 Worker 处理冻结快照。展开报告的「开发组逐折误差」，查看某组对应的训练名单、折内均值和总体标准差、中位数以及逐单预测。
6. 09:30，业务负责人林桥检查渡口组独立 MAE、稀疏系数和 `QY-0609` 的实际工时，点击「复核并发布」。
7. 09:40，观察员许禾打开已发布报告，用后续同规格视频的 5.5 分钟、22 镜头、2 次换景试估，记录结果到次日排期表。输入 180 分钟、950 镜头、90 次换景会显示外推提示。
8. 09:45，下载 `sign-rework-<报告号>.csv`，按 `partition` 分离开发折与独立留出，逐单复核实际工时和两种方法的预测。CSV 每行都携带快照 SHA-256。

示例文件名指制作组上游工作表；本项目通过表单录入结算字段。

## 计算口径

1. 提交时冻结全部工单、特征方案 ID/名称/特征/α、方法版本和留出组。按工单号排序，用规范 JSON 计算 SHA-256，Worker 开始计算前验证哈希。此后的工单修订只影响新比选。
2. 先从数据集取走独立留出组。开发集使用 Leave-One-Group-Out，每折取一支完整摄制组验证，其余开发组训练。摄制组必须从名册选择，组代码不作为模型输入。
3. 每个训练折独立求特征均值 `μ` 和总体标准差 `σ`，用 `z = (x - μ) / σ`。将同一训练参数用于本折验证样本，常量列的系数为零。中位数基线只取该训练折的实际工时中位数。
4. 对标准化后的训练折解 `min (1/(2n))·Σ(y - b - zβ)² + α·Σ|β|`。截距 `b` 为训练目标均值且不参与惩罚，系数用循环坐标下降及软阈值求解。用 `β/σ` 和 `b - Σ(μβ/σ)` 换回原尺度。Lasso 预测下限为 0 h，记录**未四舍五入**的误差。[坐标下降算法出处](https://doi.org/10.18637/jss.v033.i01)
5. 单组 MAE 是该组 `mean(|预测 - 实际|)`。开发组各折的 MAE 等权平均，两方法中更低者入选，差值在 `1e-9 h` 内选择中位数。用整个开发集重新训练两方法后，只在独立留出组打最终分；留出组误差不参与选型。
6. 试估使用冻结报告中的入选模型。每项被选特征超出开发集取值区间时提示外推。原尺度系数表示其余特征固定时，相应特征增加一个单位对应的工时变化。

每次比选需要至少 3 个有标注摄制组，每组至少 2 条结算工单，合计不超过 600 条。非白名单特征、非法字段、无样本的留出组在入队前拦截。求解 5,000 次循环仍未收敛时，报告进入失败状态，分析员可提高 α 或少选共线特征后再次提交。

## 本地运行

```bash
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

| 服务 | 实现 | 本机入口 |
| --- | --- | --- |
| `frontend` | Nginx 与原生 HTML/CSS/JS，代理 `/api/` | `http://127.0.0.1:18278` |
| `backend` | Python 3.11、FastAPI、psycopg、JWT | `http://127.0.0.1:19278/docs` |
| `worker` | Python 进程，PostgreSQL 行锁队列、心跳健康检查 | 容器内运行 |
| `db` | PostgreSQL 16 | `127.0.0.1:17778` |
| `redis` | Redis 7，用于认证入口限流 | 容器内运行 |

`SEED_DEMO=true` 会在 API 启动时填充演示数据。脚本按邮箱、工单号、版本名称去重，保留已有编辑。`docker compose logs backend worker` 可用于本地调试。修改后用 `docker compose up -d --build --wait` 重建。关闭开发栈可运行 `docker compose down`，需要完整清除演示数据时加 `-v --remove-orphans`。

`.env.example` 给出本机默认值。`COMPOSE_PROJECT_NAME` 是容器命名前缀，`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 控制本机端口，`NETWORK_SUBNET` 默认 `10.221.209.0/24`。`DB_PASSWORD` 和 `JWT_SECRET` 用于本地开发，部署时需替换。后台容器可用 `POSTGRES_HOST`、`POSTGRES_PORT` 和 `REDIS_URL` 配置连接。`dbdata` 和 `redisdata` 分别存储数据库与缓存数据。`artifacts` 是批次要求的共享卷，报告和导出数据由 PostgreSQL 持久化。

## 代码结构

- `backend/migrations/` 管理建表和摄制组名册。`scripts/seed_demo.py` 生成演示工单和账号。
- `backend/src/routes/` 注册 API，`controllers/` 处理鉴权和业务写入，`models/` 持久化实体和审计，`services/` 执行计算、快照和导出。
- `backend/src/worker.py` 以事务锁领取任务和写入结果。进程在提交前退出时，事务回滚，任务可再次领取。
- `frontend/src/` 包含四个业务模块、API 与状态、组件、路由和界面样式。
- `test-artifacts/gb-5209/` 在批次根目录提供验收脚本、浏览器证据及运行结果。

共享枚举出现在 `backend/src/constants/domain.py`、`backend/migrations/001_initial.sql` 的约束、`backend/src/schemas/inputs.py` 的特征白名单以及 `frontend/src/constants/domain.js`。角色用于鉴权和显示操作，报告状态用于队列与发布状态，接单特征用于表单、拟合及系数展示。写入工单、创建版本、任务入队和结束、报告发布均记录审计。

## 使用边界

模拟数据只有 6 支摄制组，留出组表现用于复核这一次排期口径。请提前约定留出组及版本的选择规则；反复用同一个独立留出组的误差调整 α 或特征会破坏后续独立评估。当前试估提供点估计，暂无预测区间。摄制组名册通过数据库迁移维护，工时按单条结算录入。演示栈面向本机，默认启用种子账号。
